# AGENTS.md 初始化

为当前项目建立一份可长期复用的根目录 `AGENTS.md`。它是给 AI 的项目工作合同，记录项目背景、真实命令、目录约定、代码规范、改动边界和当前进度。这个 skill 只负责规则文档，不负责实现业务功能。

## 先判断目标文件状态

先检查项目根目录：

- 没有 `AGENTS.md`：创建初稿。
- 已有 `AGENTS.md`：先完整读取，默认做增量更新，不覆盖、不重排无关内容。
- 找到多个层级的 `AGENTS.md`：说明根目录文件和子目录文件的作用范围，避免把局部规则误当成全局规则。

如果用户只要求查看或建议，不要直接写文件；只有用户明确要求初始化、创建或更新时才编辑。

## 读取真实项目事实

按优先级读取：

1. `README.md` 和现有 `docs/` 文档。
2. `package.json`、锁文件、构建配置、测试配置和 CI 配置。
3. 源码目录、测试目录和脚本目录。
4. Git 状态（只读），用于了解当前进度和未提交改动。

从这些文件提取项目名称、用途、技术栈、启动命令、构建命令、测试命令、目录结构和已知约束。找不到的内容写“未发现”或“待确认”，不要猜。

## AGENTS.md 内容

新建文件至少包含以下章节：

```markdown
# AGENTS.md

## 项目简介
## 技术栈与常用命令
## 目录结构
## 代码规范
## 工作规则
## 当前进度
```

内容要求：

- 项目简介控制在三行以内，说明项目做什么、服务谁、当前状态。
- 技术栈、启动、构建和测试命令必须来自项目文件；命令不确定就标记待确认。
- 目录结构只记录当前存在且有意义的目录，不要提前虚构未来模块。
- 代码规范优先复用现有配置和代码风格；没有证据时写“沿用现有代码风格”。
- 当前进度区分已完成、进行中、待办；不要把聊天中的愿望写成已完成。

## 默认工作规则

如果项目没有已有规则，可以加入以下最小规则：

- 改动前先说明目标、涉及文件和验证方式。
- 只改与当前任务相关的文件，不删除或重命名未授权文件。
- 不擅自引入新依赖；确有必要时先说明原因。
- 遇到不确定的业务或技术事实，先标记并询问，不要猜。
- 每次改动后说明修改了哪些文件以及如何验证。
- 保留现有错误处理、数据校验和安全边界。

如果已有规则与这些默认规则冲突，以用户明确要求和项目已有约定为准，并保留冲突说明。

## 更新策略

- 写入前先展示准备新增或修改的章节摘要；如果用户明确授权直接更新，可直接编辑并在完成后报告变更。
- 使用最小改动，保留原文件中仍有效的内容和顺序。
- 不把临时调试信息、密码、令牌、私钥或个人敏感信息写入文件。
- 不因为初始化 `AGENTS.md` 而修改业务代码、依赖、配置或 Git 历史。
- 完成后重新读取文件，检查 Markdown 结构、命令来源和章节是否齐全。

## 输出报告

完成后用大白话说明：

1. 创建了还是更新了哪个文件。
2. 读取了哪些项目事实。
3. 写入了哪些主要规则。
4. 哪些内容仍待用户确认。
5. 没有执行哪些命令（如果命令可能改变项目状态）。
